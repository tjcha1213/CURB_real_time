## Tools used

- **Claude Code (Anthropic, Claude Opus 4.7 / 1M-context)** running inside VS Code, in agent mode with file-edit, shell, and git access.
- **Google NotebookLM** for the 90-second introductory video (Audio/Video Overview generated from a curated source bundle).
- **Google Apps Script** (no AI) for the petition's Sheet backend.
- All other research, design judgment, source vetting, and data validation was done by the team.

## Workflow — paragraph version

I used Claude Code as a **pair-programming agent**, not as a content generator. The workflow looped through three phases on every feature: **frame the intent in plain English**, let the agent draft the implementation, then **read its work and steer**. I never accepted a number, a chart, or a copy line that I had not personally checked against the underlying source. Source vetting (which CKAN resource ID, which MassDEP PDF page, which 2022 ban citation) was done up front by the agent under explicit instruction to mark anything unverified, and I cross-checked the dataset IDs against live portal pages before wiring any of them into the data pipeline. For the storytelling site itself, the agent scaffolded React components and D3 charts from a written project brief I had drafted (`CLAUDE.md`); I directed the narrative spine, the editorial voice, the design palette, and every "we propose…" claim. For the prototype app and the closing video section, I described the flows in conversation and the agent translated them into screens and components, which I then critiqued and iterated on with the agent until they matched our intent.

---

## Workflow — bullet version

- **Frame, don't dictate.** Each session started with me writing a short brief (the goal, the audience, what to avoid). The agent proposed the implementation. I rejected drafts that ignored project conventions and reissued the brief.
- **Source first, code second.** Before any data was fetched, I asked the agent to verify dataset IDs against live open-data portals and report only what it could confirm. Verified IDs went into `docs/data-sources.md` with citations.
- **Read every diff.** Every file edit was reviewed in VS Code before commit. The git history is the audit trail — every commit message documents the actual change, not "AI commit."
- **Editorial decisions stayed human.** The seven-act narrative spine, the headline copy, the policy proposal numbers, the choice of what to include vs. cut — all team-authored.
- **Design system was a constraint, not a suggestion.** I drafted `CLAUDE.md` with explicit "do not use Recharts / Material UI / dashboard chrome / generic AI aesthetics," and held the agent to it.
- **The agent ran the data pipeline.** Python scripts that fetch from Cambridge Socrata + Boston CKAN + MassDEP were drafted by the agent under my supervision and corrected when the schemas turned out to differ from the agent's first guess.
- **Limits were named, not hidden.** When the agent's bulky-item 311 filter accidentally matched only 2 of 5 categories, we caught it and the chart caption now flags that the data only goes back to 2024. We ship known limitations, not silent ones.

## Representative prompt log

The full conversation is too long to include verbatim, so the list below is the substantive prompts only — the ones that actually shaped a deliverable. Trivial chat ("open the site," "won't play," "broken," etc.) and routine confirmations are omitted. Prompts originally written in Japanese have been translated to English; long context blocks (the project brief, the dataset, the source CSV) are referenced rather than quoted.

### Project bootstrap

- **"Read CLAUDE.md in full and proceed."** — pointed the agent at the written project brief and let it scaffold the Next.js + Tailwind + D3 stack.

### Data pipeline

- **Research brief (verbatim, English):** *"Find exact dataset identifiers and published numbers for a Massachusetts bulky-waste / furniture data-journalism site … return a structured markdown report with verified Cambridge Socrata IDs, Boston CKAN resource IDs, MassDEP figures, MRC data, and ACS table IDs. Mark anything unverified — I'd rather have one confirmed ID than four guesses."*
- **"Bundle all the CSVs into a single Excel file."** — produced [`public/data/the-curb-data.xlsx`](../public/data/the-curb-data.xlsx) with an `_index` tab.

### Visualizations

- **"Add a map element and a video placeholder to the site."** — kicked off the Scene 4 map and the Scene 1 hero video slot.
- **"Make the map interactive."** — escalated from a static dot map to a Leaflet build with priority filter, hover tooltip, click-to-pin detail panel, and a jump-to dropdown.
- **"The map is hard to read on desktop — width isn't constrained."** — restructured Scene 4 so the map gets a full-width row and the inner sidebar/map split fits.
- **"Should the location list be a dropdown?"** — replaced the long location list with a grouped `<select>`.
- **"Scene 3, second chart — why is 2026 so high?"** — agent investigated, found a 311-type filter string mismatch (only 2 of 5 categories were matching), reported it honestly, and offered three remediation options.

### Design integration

- **"Integrate the design from version2.pdf — list what to merge, what to keep, and what to drop."** — produced a bilingual integration plan in bullet form.
- **"From `curb-the-pile.html`, pull in the city-side demo and the resident-side demo. Also add the petition form from the PDF version."** — the brief that produced Scene 8 (mobile mockup + dashboard mockup + four demands + petition form).
- **"Add '(Coordinated Urban Recycling for Boston)' next to 'The Curb' in the branding."** — wordmark expansion across AppShell, footers, and video credits.

### Prototype app

- **"On a separate page, mock up the reporting system / pickup application that the site proposes."** — produced `/app`, `/app/report`, `/app/browse`, `/app/dashboard`.
- **"It's really just for the demo, so keep it light — screen transitions are enough."** — simplified the app from interactive form state machines to presentational mockups.
- **"There's a finished intro video at `The_Curb__MA_Waste_Story.mp4` — wire it into the Scene 1 placeholder."** — replaced the placeholder with the NotebookLM intro video and updated the `VideoHero` component to support an "intro" mode (controls visible, plays once) alongside the original "ambient" mode (autoplay-loop-mute).
- **"There's a PR video at `public/videos/ourmovie.mp4` — embed it as a closing section at the very bottom."** — produced the `AppDemoFinale` section.

### Backend wiring

- **"The petition should write to a Google Sheet, and add a live signature counter."** — agent designed an Apps Script Web App that appends rows to a Sheet and returns `{ count }`; the form was rewritten to POST submissions, GET the count on mount, and render a progress bar against a 5,000-signature goal. Setup steps live in [`docs/petition-backend/README.md`](./petition-backend/README.md).

### Deployment

- **"Host this on GitHub Pages."** — set up `output: "export"`, basePath gating, the `.github/workflows/deploy.yml` workflow, and a `.nojekyll` file. Subsequent secret wiring (`PETITION_ENDPOINT`) was discussed in chat and committed to the workflow.

### NotebookLM video

- The full English prompt for the 60-second introductory video lives at [`notebooklm/03-prompt.md`](../notebooklm/03-prompt.md). Excerpt:
  > *"Make a 60-second introductory video for a Harvard Kennedy School data-journalism project called The Curb … Aim for ~150 spoken words. Open on Allston Christmas — 1,700 mattresses on Boston curbs in one weekend. Do NOT speak any URL. Each number gets its source named in the same beat. Style references: The Pudding, NYT Upshot, FT Visual Journalism."*

### Presentation prep

- **"I'm presenting this today — propose a structure for talking about how and why we built the site, in JP + EN bullets."** — produced a presentation outline.
- **"I want to walk through the site top to bottom, explaining each chart as I go."** — produced a scene-by-scene walkthrough script.
